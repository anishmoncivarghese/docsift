# DocSift Milestone 5: Local Search — Implementation Plan

**Goal:** Add fast, fully local keyword and phrase retrieval that returns ranked,
token-budgeted chunks with document, page, section, and chunk metadata, without
returning the complete document.

**Architecture:** SQLite FTS5 stores one row per normalized `Chunk`. Chunk text and
the joined section path are searchable; document identity, position, pages, section
metadata, and token count are retained as unindexed columns. Successful background
jobs replace a document's index atomically after artifacts are stored. The API calls
a small retrieval service that validates query controls, ranks candidates with
FTS5/BM25, optionally expands adjacent context, and enforces result-count and token
budgets. Deletion removes index rows in the same transaction as document metadata.

**Technology:** Existing Python 3.11/3.12, SQLite FTS5, FastAPI, Pydantic v2,
pytest, Ruff. No new dependency.

## Global constraints

- Preserve lazy engine imports and the engine-neutral core model boundary.
- Never log or place document text in errors.
- Use parameterized SQL for values. Treat the FTS query as data and convert invalid
  FTS syntax into a stable domain/API error rather than exposing SQLite errors.
- All conversion/API tests isolate both `DOCSIFT_DATA_DIR` and
  `DOCSIFT_CACHE_DIR`.
- New behavior follows RED → GREEN → refactor. Confirm each new test fails against
  the pre-change implementation.
- Unit tests and Ruff must pass after every task. Integration tests remain excluded
  by the default pytest configuration.
- Do not add embeddings, vector storage, reranking models, cross-document search,
  authentication, or answer generation. Those are outside Milestone 5.

## API contract

```text
GET /v1/documents/{document_id}/search
    ?q=operational+risk
    &limit=5
    &max_tokens=5000
    &context=0
```

- `q`: required, non-blank keyword or quoted-phrase query.
- `limit`: number of direct matches, default 5, range 1–20.
- `max_tokens`: total returned token budget, default 5000, range 1–20000.
- `context`: adjacent chunks on each side, default 0, range 0–2.
- `404`: document does not exist or has no stored result.
- `422`: invalid query/control values.
- Response contains `document_id`, `query`, `estimated_tokens`, and ordered
  `results`. Each result contains `chunk_id`, `text`, `estimated_tokens`,
  `section_path`, `pages`, `score`, `match`, and `context_for`.
- `match=true` identifies a direct FTS match. Expanded neighbors have
  `match=false` and name the direct match in `context_for`.
- The same chunk is returned at most once, even when it is context for multiple
  matches. Direct matches win over context copies.

## Task 1: FTS schema and storage primitives

**Files:**

- Modify `src/docsift/storage/database.py`
- Modify `tests/unit/test_database.py`

**Interfaces:**

- Add virtual table `document_chunks` using FTS5 columns:
  `document_id UNINDEXED`, `chunk_id UNINDEXED`, `position UNINDEXED`,
  `section`, `text`, `pages UNINDEXED`, `estimated_tokens UNINDEXED`.
- `index_document_chunks(document_id: str, chunks: list[Chunk]) -> None`
  replaces all rows for that document in one transaction.
- `search_document_chunks(document_id: str, query: str, limit: int) -> list[dict]`
  returns BM25-ranked direct matches and metadata; phrase syntax supported by FTS5.
- `get_indexed_chunks(document_id: str, positions: list[int]) -> list[dict]`
  retrieves positional neighbors without running FTS.
- `delete_document()` deletes indexed rows and the document metadata atomically.

**Tests:** FTS5 table creation/idempotency, keyword ranking, quoted phrase matching,
section-heading matching, document isolation, metadata round-trip, replacement on
re-index, positional lookup, empty chunks, and index removal on delete.

## Task 2: Index successful conversions

**Files:**

- Modify `src/docsift/services/job_service.py`
- Modify `tests/unit/test_job_service.py`

After `store_result()` and before marking the job succeeded, call
`index_document_chunks(result.document_id, result.chunks)`. An indexing failure must
fail the job rather than claim that a document is searchable when it is not. A
re-upload/cache hit re-indexes idempotently. Cancellation checks remain before all
persistent writes.

**Tests:** successful job is searchable, repeated conversion does not duplicate
rows, failed/cancelled jobs are not indexed, and indexing failure yields a failed
job without exposing document content.

## Task 3: Search service and response models

**Files:**

- Create `src/docsift/services/search_service.py`
- Modify `src/docsift/api/schemas.py`
- Create `tests/unit/test_search_service.py`

Define `SearchResult` and `SearchResponse` Pydantic models. Implement
`search_document(document_id, query, limit=5, max_tokens=5000, context=0)`.
Normalize surrounding whitespace but preserve quoted phrases. Reject blank queries.
Fetch ranked direct matches, expand `position ± context`, deduplicate, preserve
direct-match rank and document order within each context group, and stop before the
token budget is exceeded. A single chunk larger than the remaining budget is not
returned. Scores are relevance-ordering diagnostics, not stable public thresholds.

**Tests:** ranking, token limit, result limit, context expansion, boundary context,
deduplication, direct-match precedence, blank/invalid FTS query handling, and no
full-document fallback when there are no matches.

## Milestone 5 exit criteria

- Keyword and quoted-phrase search returns relevant ranked chunks.
- Results never silently fall back to complete Markdown.
- Every result carries document, page, section, and chunk metadata.
- Context expansion and token/result limits are enforced.
- Re-index and deletion are correct and idempotent.
- Search remains fully local and requires no new model or external API.
- Full unit, lint, and formatting gates pass.
